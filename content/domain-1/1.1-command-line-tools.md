### Why text tools still matter
- Configs, `show` output, logs, and API replies are all text; small ==command-line tools== each do one job and chain together with ==pipes==
- The files used below

```text label="sw1.cfg"
hostname core-sw1
!
ntp server 10.0.0.5
snmp-server community public RO
!
interface Gi0/1
 description uplink to dist-sw2
!
interface Gi0/2
 description spare
 shutdown
!
```

```json label="inv.json"
[
  {"name": "core-sw1", "site": "CLT",
   "status": "active", "vlans": [10, 20]},
  {"name": "dist-sw2", "site": "CLT",
   "status": "offline", "vlans": [10]},
  {"name": "edge-rtr1", "site": "RDU",
   "status": "active", "vlans": []}
]
```

### grep: find lines
- ==grep== prints lines that match a pattern
  - `-i` ignore case; `-v` invert (non-matching lines); `-c` count; `-n` line numbers
  - `-E` extended regex; `-o` only the matching part; `-r` search a folder; `-l` file names only
  - `-A 2` / `-B 2`: lines after / before each match, for context
- ==Exit status== 0 if anything matched, 1 if not
  - `grep -q` prints nothing and is made for `if` tests

```console label="Terminal"
$ grep -n shutdown sw1.cfg
11: shutdown
$ grep -c '^interface' sw1.cfg
2
```

### awk: work with columns
- ==awk== splits each line into ==fields==: `$1`, `$2`, ..., `$NF` (the last)
  - Splits on whitespace by default; `-F,` splits on commas
- A program is `pattern { action }`: the action runs only on matching lines
  - `NR` is the line number, so `NR > 1` skips a header row
  - `END { }` runs after the last line (totals)

```text label="inv.csv"
name,site,ip
core-sw1,CLT,10.0.0.11
dist-sw2,CLT,10.0.0.12
edge-rtr1,RDU,10.1.0.1
```

```console label="Terminal"
$ awk -F, 'NR > 1 {print $3, $1}' inv.csv
10.0.0.11 core-sw1
10.0.0.12 dist-sw2
10.1.0.1 edge-rtr1
$ awk -F, '$2 == "CLT" {n++} END {print n}' inv.csv
2
```

### sed: edit a stream
- ==sed== edits text line by line as it flows through
  - `s/old/new/` substitutes the first match on each line; add `g` for every match
  - `/pattern/d` deletes matching lines
  - `-n '/start/,/end/p'` prints only a range of lines
- Output goes to the screen; the file is untouched unless you add `-i`
  - `-i.bak` edits ==in place== and keeps a backup copy
  - Escape the dots in IP addresses, or `10.0.0.5` also matches `10a0b0c5`

```console label="Terminal"
$ sed -n '/^interface Gi0\/2/,/^!/p' sw1.cfg
interface Gi0/2
 description spare
 shutdown
!
$ sed -i.bak 's/10\.0\.0\.5/10.0.0.6/' sw1.cfg
$ diff sw1.cfg.bak sw1.cfg
3c3
< ntp server 10.0.0.5
---
> ntp server 10.0.0.6
```

### jq: query JSON
- ==jq== filters and reshapes JSON, the format of nearly every REST API reply
  - `.` the whole document; `.name` one key; `.[]` each array item; `|` chains steps
  - `select(condition)` keeps only matching items
  - `-r` ==raw output== (no quotes) for Bash loops; `-c` compact output
  - Many APIs wrap the list in a key: NetBox replies use `.results[]`

```console label="Terminal"
$ jq length inv.json
3
$ jq -r '.[] | select(.site=="CLT") | .name' inv.json
core-sw1
dist-sw2
$ jq -c '[.[].vlans[]] | unique' inv.json
[10,20]
```

### PowerShell cmdlets
- A ==cmdlet== is a PowerShell command named `Verb-Noun`: `Get-Content`, `Select-String`, `Where-Object`, `ConvertFrom-Json`
- PowerShell pipes ==objects==, not text
  - `ConvertFrom-Json` returns objects with properties; no field counting
  - `$_` is the current object inside a script block
- PowerShell 7 (`pwsh`) runs on Windows, Linux, and macOS

:::wide
| Task | Linux tool | PowerShell cmdlet |
|---|---|---|
| Read a file | `cat file` | `Get-Content file` |
| Find matching lines | `grep pattern file` | `Select-String -Pattern p -Path file` |
| Keep matching rows | `awk '$4 == "up"'` | `Where-Object { $_.Status -eq 'up' }` |
| Pick columns or properties | `awk '{print $1}'` | `Select-Object Name` |
| Replace text | `sed 's/a/b/'` | `$text -replace 'a', 'b'` |
| Parse JSON | `jq` | `ConvertFrom-Json` / `ConvertTo-Json` |
| Count, group | `wc -l`, `sort \| uniq -c` | `Measure-Object`, `Group-Object` |
:::

```powershell label="report.ps1"
Select-String -Path ./sw1.cfg -Pattern 'shutdown' |
    ForEach-Object { "line $($_.LineNumber)" }

$devices = Get-Content ./inv.json -Raw |
    ConvertFrom-Json
$devices |
    Where-Object { $_.status -ne 'active' } |
    ForEach-Object { $_.name }
```

```console label="Terminal"
$ pwsh -NoProfile -File report.ps1
line 11
dist-sw2
```

### Pipelines
- The ==pipe== `|` sends one command's standard output into the next command's standard input
- Example: which addresses are failing SSH logins on a bastion host?

```console label="Terminal"
$ head -1 auth.log
Oct 19 08:01:12 bastion sshd[811]: Failed password for admin from 203.0.113.9 port 50122 ssh2
```

```bash label="top_ips.sh"
#!/usr/bin/env bash
set -o pipefail
grep 'Failed password' auth.log |
  awk '{print $(NF-3)}' |
  sort |
  uniq -c |
  sort -rn |
  head -3
```

```console label="Terminal"
$ ./top_ips.sh
      4 203.0.113.9
      2 198.51.100.23
      1 10.0.4.17
```

:::figure wide 1.1-text-pipeline.svg | Each stage reads the previous stage's output. The line counts on top show the data shrinking from raw log to answer.

- `$(NF-3)` counts back from the end, so it still finds the address when the line says `for invalid user bob`
- `uniq` only merges ==adjacent== duplicates: always `sort` first
- By default a pipeline's exit status is the last command's
  - `set -o pipefail` makes the pipeline fail if any stage fails, so a missing log file is not hidden by a successful `sort`

:::exam
- Match the tool to the job: grep finds lines, awk pulls columns, sed substitutes or deletes, jq queries JSON, and the PowerShell cmdlets do the same work on objects.
- Expect to complete or read a pipeline. `sort | uniq -c | sort -rn` counts and ranks; leaving out the first `sort` gives wrong counts.
- `sed -i` changes the file; without it sed only prints. A scenario that "ran sed but the file did not change" is missing `-i`.
:::
