### Remotes
- A ==remote== is a short name for another copy of the repository
  - `origin` is the name Git gives the remote you cloned from
  - A repository can have several: `origin`, `upstream`, `backup`
- `git remote -v` lists remotes and their URLs
- `git remote add origin <url>` connects an existing local repository
- Remote URLs use HTTPS or SSH
  - HTTPS: personal access token for authentication
  - SSH: key pair; `git@github.com:org/repo.git`
- ==Remote-tracking branches==
  - `origin/main` is your local, read-only record of where `main` was on the remote the last time you talked to it
  - Updated by `fetch`, `pull`, and `push`; never edited directly

### git push
- Sends your local commits to a branch on the remote
- First push of a new branch: set the upstream
  - `git push -u origin main`
  - After that, plain `git push` and `git pull` know where to go
- Tags are not pushed by default
  - `git push origin --tags`, or push one tag: `git push origin v1.2.0`
- A push is ==rejected== when the remote has commits you do not

```console label="Terminal"
$ git push
 ! [rejected]        main -> main (fetch first)
error: failed to push some refs to 'github.com:acme/netconfig.git'
hint: Updates were rejected because the remote
hint: contains work that you do not have locally.
```

- The fix is to bring those commits down first, then push again
  - Never answer a rejection with `git push --force` on a shared branch; it discards your teammates' work

### git fetch
- Downloads new commits and updates the `origin/*` branches
- Does ==not== change your working tree or your local branches
  - Always safe; nothing you are working on moves
- Use it to look before you integrate

```console label="Terminal"
$ git fetch origin
   1e5e6c6..271e551  main  -> origin/main
$ git status -sb
## main...origin/main [ahead 1, behind 1]
$ git log --oneline main..origin/main
271e551 feat: add VLAN 20
```

- `ahead 1`: you have a commit the remote does not
- `behind 1`: the remote has a commit you do not
- `main..origin/main` means "commits on origin/main that are not on main"

### git pull
- ==git pull = git fetch + integrate==
  - Integrate means merge by default, so you may get a merge commit
  - `git pull --rebase`, or set `pull.rebase true`, replays your commits on top for a straight-line history
- Pull changes your working tree
  - If you and a teammate edited the same lines, the pull stops with a ==merge conflict== (troubleshooting is objective 1.4)
- Pull before you start work and before you push

:::wide
| Command | Direction | Changes your files? | Can conflict? |
|---|---|---|---|
| `git fetch` | remote to local tracking branches | No | No |
| `git pull` | remote to your current branch | Yes | Yes |
| `git push` | your branch to remote | No | Rejected if behind |
| `git clone` | remote to a new local repository | Creates them | No |
:::

:::exam
- "Update the local view of the remote without modifying any working files" is `git fetch`. "Get the latest changes into my branch" is `git pull`.
- A rejected push is fixed by pulling (or fetching and merging) and pushing again, not by forcing. Force pushing a shared branch rewrites history other people already have.
:::

:::try Try it with two clones
Create a bare repository with `git init --bare origin.git`, clone it twice, push a commit from one clone, then run `git fetch` and `git status -sb` in the other. Commit something there too before pulling and you will see the rejected push for yourself.
:::
