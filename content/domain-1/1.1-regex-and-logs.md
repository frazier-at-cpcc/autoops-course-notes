### Application logs
- ==Application logs== are the record a program writes about what it did
  - First stop when a playbook, pipeline job, or service misbehaves; automation reads them too (count failures, alert on a pattern)
- A useful line carries a UTC timestamp, a ==log level==, the host or component, the message, and a job or request ID
- Where logs go
  - Containers: stdout and stderr, read with `docker logs`
  - systemd services: the journal; `journalctl -u nginx -p err` shows only errors
  - Files under `/var/log/`, rotated by `logrotate`; central platforms (syslog, Elastic, Loki, Splunk) collect from every host
- Never log secrets: passwords, API tokens, session cookies

### Log levels
- A ==log level== ranks how serious a message is
- The configured level is a ==threshold==: that level and everything more severe is written; anything less severe is dropped
  - Production usually runs at INFO or WARNING
  - Switch to DEBUG while troubleshooting, then switch back (DEBUG is noisy and may expose data)

| Syslog code | Syslog severity | Python `logging` |
|---|---|---|
| 0 | Emergency | |
| 1 | Alert | |
| 2 | Critical | `CRITICAL` (50) |
| 3 | Error | `ERROR` (40) |
| 4 | Warning | `WARNING` (30) |
| 5 | Notice | |
| 6 | Informational | `INFO` (20) |
| 7 | Debug | `DEBUG` (10) |

- Syslog: a ==lower number is more severe==; Python: a higher number is more severe
- Python's `logging` writes to stderr by default

```python label="job.py"
import logging
import os

logging.basicConfig(
    level=os.environ.get("LOG_LEVEL", "INFO"),
    format="%(levelname)-8s %(name)s: %(message)s",
)
log = logging.getLogger("backup")
log.debug("opening SSH to core-sw1")
log.info("core-sw1 saved 412 lines")
log.warning("dist-sw2 slow reply 4.8s")
log.error("edge-rtr1 auth failed")
```

```console label="Terminal"
$ python3 job.py
INFO     backup: core-sw1 saved 412 lines
WARNING  backup: dist-sw2 slow reply 4.8s
ERROR    backup: edge-rtr1 auth failed
$ LOG_LEVEL=ERROR python3 job.py
ERROR    backup: edge-rtr1 auth failed
$ LOG_LEVEL=DEBUG python3 job.py 2>&1 | head -1
DEBUG    backup: opening SSH to core-sw1
```

### Structured vs. unstructured logs
- ==Unstructured logs== are free text written for people
  - Easy to read; hard to parse reliably
  - Pulling out a field takes a regular expression, and a format change breaks it
- ==Structured logs== write every event as fields, usually one JSON object per line (JSON Lines)
  - Machines filter by field name; no pattern guessing
  - Log platforms index the fields for search and dashboards

```text label="backup.log (unstructured)"
08:14:02 INFO core-sw1 saved 412 lines
08:14:05 WARNING dist-sw2 slow reply 4.8s
08:14:09 ERROR edge-rtr1 auth failed from 10.0.4.17
08:14:11 INFO dist-sw3 saved 388 lines
08:14:20 ERROR edge-rtr2 timeout after 30s
08:14:26 ERROR edge-rtr1 auth failed from 10.0.4.17
```

```json label="backup.jsonl (structured)"
{"level":"info","host":"core-sw1","lines":412}
{"level":"error","host":"edge-rtr1","err":"auth"}
{"level":"error","host":"edge-rtr2","err":"timeout"}
```

```console label="Terminal"
$ jq -r 'select(.level=="error").host' backup.jsonl
edge-rtr1
edge-rtr2
```

### Regular expression building blocks
- A ==regular expression (regex)== is a pattern that describes text
  - Search (does a line match?), extract (pull out the IP), validate (is this a hostname?), replace

:::wide
| Pattern | Matches | Example |
|---|---|---|
| `.` | any single character | `Gi0.1` matches `Gi0/1` and `Gi0.1` |
| `\d` `\w` `\s` | a digit; a letter, digit, or `_`; whitespace | `\d+` matches `412` |
| `[A-Z]` `[^ ]` | one character from a set; any character not in it | `[0-9a-f]` is one hex digit |
| `^` `$` | start of line; end of line | `^interface` |
| `*` `+` `?` | previous item 0 or more times; 1 or more; 0 or 1 | `vlans?` matches `vlan` and `vlans` |
| `{3}` `{1,3}` | exactly 3; between 1 and 3 | `\d{1,3}` is one IPv4 octet |
| `( )` | group, and capture what matched | `(\d+) lines` captures `412` |
| `a\|b` | either side | `ERROR\|CRITICAL` |
| `\.` `\b` | a literal dot; a word boundary | `10\.0\.4\.17` |
:::

- `*` and `+` are ==greedy==: they take as much text as possible
  - Add `?` for the shortest match: `".*?"` stops at the first closing quote
- Escape characters that have a meaning (`. * + ? ( ) [ ] { } | \ ^ $`) when you mean them literally
  - An unescaped `.` in `10.0.4.17` also matches `10a0b4c17`
- Anchor patterns with `^` and `$` when validating whole values

### Extracting fields from log lines
- ==Capture groups== turn one unstructured line into named fields
  - Python `(?P<name>...)` makes a ==named group==; read it back as `m["name"]`

```python label="parse_log.py"
import re
from collections import Counter

LINE = re.compile(
    r"^(?P<time>\d{2}:\d{2}:\d{2}) "
    r"(?P<level>[A-Z]+) "
    r"(?P<host>[\w-]+) "
    r"(?P<msg>.*)$"
)
levels = Counter()
with open("backup.log") as f:
    for line in f:
        m = LINE.match(line.rstrip("\n"))
        if not m:
            continue    # skip other formats
        levels[m["level"]] += 1
        if m["level"] == "ERROR":
            print(f'{m["host"]:<10} {m["msg"]}')
print(dict(levels))
```

```console label="Terminal"
$ python3 parse_log.py
edge-rtr1  auth failed from 10.0.4.17
edge-rtr2  timeout after 30s
edge-rtr1  auth failed from 10.0.4.17
{'INFO': 2, 'WARNING': 1, 'ERROR': 3}
```

### Regex flavors on the command line
- Tools speak different dialects
  - ==Basic (BRE)==: `grep`, `sed` by default; `+ ? | ( ) { }` need a backslash to be special
  - ==Extended (ERE)==: `grep -E`, `sed -E`, `awk`; those characters work bare
  - ==Perl-compatible (PCRE)==: `grep -P`; adds `\d`, lazy `*?`, lookarounds; Python `re` and PowerShell `-match` use similar Perl-style syntax
- `\d` is not part of BRE or ERE
  - GNU `grep -E '\d'` matches the letter `d`, so the count below is 0

```console label="Terminal"
$ grep -c ERROR backup.log
3
$ grep -cE '^\d' backup.log
0
$ grep -cP '^\d' backup.log
6
$ grep -oE '([0-9]{1,3}\.){3}[0-9]{1,3}' backup.log
10.0.4.17
10.0.4.17
```

:::exam
- Expect to pick the regex that matches a sample line or extracts one field. Check anchors, escaped dots, and quantifiers: `\d{1,3}` versus `\d+` versus `\d*`.
- Know the severity order. Syslog 0 (Emergency) is the most severe and 7 (Debug) the least; setting a level shows that level and everything more severe.
- Structured (JSON) logs are filtered by field with a tool like `jq`; unstructured text needs a regex.
:::
