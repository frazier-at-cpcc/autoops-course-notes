### Merge conflicts
- Three ==Git errors== come up again and again: merge conflicts, authentication issues, and detached HEAD
- A ==merge conflict== happens when two branches change the same lines, or one edits a file the other deleted
  - Git merges different lines on its own; it stops only when it cannot choose
- Any command that combines histories can hit one: `merge`, `pull`, `rebase`, `cherry-pick`, `stash pop`
- Here `main` and `feature/ntp` both changed the NTP server line (branching basics are in objective 1.2)

```console label="Terminal"
$ git merge feature/ntp
Auto-merging switch.cfg
CONFLICT (content): Merge conflict in switch.cfg
Automatic merge failed; fix conflicts and then commit the result.
$ git status --short
UU switch.cfg
```

- `UU` (`both modified` in long `git status`) marks an unmerged file
- Git writes both versions into the file between ==conflict markers==

```text label="switch.cfg (during the conflict)"
hostname core-sw1
<<<<<<< HEAD
ntp server 10.0.0.3
=======
ntp server 10.0.0.2
>>>>>>> feature/ntp
logging host 10.0.0.50
```

| Marker | Starts |
|---|---|
| `<<<<<<< HEAD` | your side: the branch you are on |
| `\|\|\|\|\|\|\| <base>` | the original text (zdiff3 style only) |
| `=======` | the incoming side |
| `>>>>>>> feature/ntp` | end of the incoming side |

### Resolving a conflict
- Edit the file to the final content you want: one side, the other, or a mix
  - Delete every marker line; `git commit` will not stop you from committing them
- `git add` the file to mark it ==resolved==, then finish
  - Merge: `git commit` (the message is prefilled)
  - Rebase: `git rebase --continue`
- Not ready? `git merge --abort` (or `git rebase --abort`) puts everything back
- Keep one whole side of a file with ==ours or theirs==: `git checkout --ours switch.cfg` or `--theirs`
  - During a rebase the names swap: "ours" is the branch you are rebasing onto
- `git config --global merge.conflictStyle zdiff3` adds a `||||||| 309f3f2` section holding the original line (`ntp server 10.0.0.1`), so you can see what both sides changed
- Before committing, let Git find leftover markers: `git diff --check` prints `switch.cfg:2: leftover conflict marker` and exits non-zero
- Fewer conflicts: short-lived branches, pull `main` often, run the formatter so whitespace never conflicts

### Authentication issues
- Two transports, two kinds of credential
  - HTTPS: username plus a ==personal access token== (PAT) used as the password
  - SSH: a ==key pair==; the public key is registered on your account, the private key never leaves your machine
- GitHub stopped accepting account passwords for Git in August 2021
  - Using one is rejected with "Invalid username or token. Password authentication is not supported for Git operations."
- Lab output below comes from a private Gitea server over plain HTTP; Git prints the same failures over HTTPS (Gitea adds `remote: Verify`)
- A stored token that has expired or been revoked

```console label="Terminal"
$ git pull
remote: Verify
fatal: Authentication failed for 'http://git.corp.example:3000/ada/netconfig.git/'
```

- Fix: create a new token, then replace the cached one
  - The ==credential helper== caches the old token; `git credential reject` (or Windows Credential Manager, macOS Keychain) removes the stale entry and the next command asks again
- A pipeline job with no credential cannot prompt, so it fails at once
  - Git reports "could not read Username for '...': terminal prompts disabled"
  - Give the job a token from the CI secret store, or a read-only deploy key
- SSH, with a key that is not on the account

```console label="Terminal"
$ ssh -T git@git.corp.example
git@git.corp.example: Permission denied (publickey).
```

- `ssh -T` tests authentication without Git in the way; `ssh -vT` lists each key offered
- Once the public key is on the account, the same test succeeds; GitHub answers "Hi *username*! You've successfully authenticated, but GitHub does not provide shell access."
- `git remote -v` shows which transport a clone uses; `git remote set-url origin git@...` switches it

:::wide
| Message (transport) | Likely cause | Fix |
|---|---|---|
| Authentication failed for '&lt;url&gt;' (HTTPS) | wrong, expired, or revoked token; password used | new token; clear the cached credential |
| could not read Username ... terminal prompts disabled (HTTPS) | no credential and no terminal (CI job) | token from the CI secret store |
| Repository not found, or HTTP 403 (HTTPS) | token scope or repository access missing | grant access or a token with write scope |
| Permission denied (publickey). (SSH) | key not on the account, wrong key, empty agent | add the `.pub` key; `ssh-add`; check with `ssh -vT` |
| Host key verification failed. (SSH) | server key unknown or changed | verify the fingerprint; a surprise change can mean interception |
| UNPROTECTED PRIVATE KEY FILE! (SSH) | private key readable by others | `chmod 600 ~/.ssh/id_ed25519` |
:::

### Detached HEAD
- Normally `HEAD` names a branch, and the branch names a commit
- ==Detached HEAD==: `HEAD` points straight at a commit, with no branch in between

:::figure wide 1.4-detached-head.svg | A commit made with HEAD detached is attached to nothing. Give it a branch before you switch away, or recover it from the reflog afterwards.

- How you get there
  - `git checkout v1.0.0` or `git checkout <commit>` to inspect an old version
  - `git switch --detach`, an interrupted rebase, `git bisect`
  - CI runners check out the exact commit ID, so jobs usually run detached

```console label="Terminal"
$ git checkout v1.0.0
Note: switching to 'v1.0.0'.

You are in 'detached HEAD' state.
HEAD is now at 309f3f2 feat: baseline config
$ git status
HEAD detached at v1.0.0
```

- Looking around is harmless; trouble starts when you commit
  - The commit exists, but no branch points at it
  - `git push` fails: `fatal: You are not currently on a branch.`

- Recover it with the ==reflog==, the local record of everywhere `HEAD` has been

```console label="Terminal"
$ git commit -am "fix: add login banner"
[detached HEAD bc51973] fix: add login banner
$ git switch main
Warning: you are leaving 1 commit behind, not connected to
any of your branches:

  bc51973 fix: add login banner
$ git reflog -3
bc51973 HEAD@{1}: commit: fix: add login banner
309f3f2 HEAD@{2}: checkout: moving from main to v1.0.0
$ git branch hotfix/banner bc51973
$ git push -u origin hotfix/banner
```

- Better: before committing while detached, run `git switch -c hotfix/ntp` right where you are
- The reflog is local only; by default entries for unreachable commits expire after 30 days, then garbage collection deletes the commits

:::exam
- "Git reports `CONFLICT (content)`" means: edit the file, remove the markers, `git add`, commit. "Start over" is `git merge --abort`.
- "Authentication failed" on an HTTPS remote points to the token (expired, revoked, missing scope, or a password used instead). "Permission denied (publickey)" points to the SSH key. Match the message to the transport.
- "Commits made after checking out a tag are missing" is detached HEAD. The answer is `git reflog` to find the commit ID, then `git branch <name> <id>` or `git switch -c`.
:::

:::try
Clone any repository, run `git checkout HEAD~1`, and make a commit. Switch back to your branch, read the warning, then use `git reflog` to find the commit and save it on a new branch.
:::
