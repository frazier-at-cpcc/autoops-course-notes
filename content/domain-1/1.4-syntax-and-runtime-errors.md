### Two kinds of failure
- ==Syntax error==: the code breaks the grammar of its language, so the parser rejects the file before anything runs
  - Missing colon, unclosed brace or quote, bad YAML indentation
  - Not even line 1 executes
- ==Runtime error==: the code is valid, but something fails while it executes
  - Host unreachable, file missing, permission denied, key not in the data
  - Everything before the failing line already ran, so a target can be left half-configured
- ==Undefined variable errors== land in either group, depending on the tool
  - Python and Ansible find them only when that line runs
  - Terraform, `shellcheck`, and Python linters catch them before anything runs
- Rule for pipelines: run the cheap syntax checks first, before anything touches a device

:::wide
| Language | Check without running | Linter that also finds undefined names |
|---|---|---|
| Python | `python3 -m py_compile app.py` | `ruff check`, `pylint`, `flake8` |
| Bash | `bash -n script.sh` | `shellcheck` |
| PowerShell | parsed when the script loads | `Invoke-ScriptAnalyzer` (PSScriptAnalyzer) |
| Terraform | `terraform validate`, `terraform fmt -check` | `tflint` |
| Ansible | `ansible-playbook --syntax-check` | `ansible-lint` |
| YAML, JSON | `yamllint`, `jq . file.json` | |
:::

### Python: syntax errors and tracebacks
- A syntax error points at the line and column where the parser gave up
  - The real mistake can be on that line or just before it

```console label="Terminal"
$ python3 vlans.py
  File "vlans.py", line 4
    for vid in vlan_ids
                       ^
SyntaxError: expected ':'
```

- An ==undefined variable== in Python is a `NameError`, raised only when that line runs
  - Here the loop variable is `vlan_id` but line 4 says `vlanid`
  - `py_compile` passes; the script prints `rendering`, then fails
  - Python 3.10 and later suggest the closest name

```console label="Terminal"
$ python3 render.py
rendering
Traceback (most recent call last):
  File "render.py", line 9, in <module>
    print(render({10: "users"}))
          ~~~~~~^^^^^^^^^^^^^^^
  File "render.py", line 4, in render
    lines.append(f"vlan {vlanid}")
                         ^^^^^^
NameError: name 'vlanid' is not defined. Did you mean: 'vlan_id'?
```

- Reading a ==traceback==
  - Start at the last line: the exception type and message
  - Frames run from the outermost call down to the failure ("most recent call last"); the lowest frame in your own code is usually the bug

### Runtime errors
- The same code works against one device and fails against another; the environment is the cause
- A push to a device whose service is down

```console label="Terminal"
$ python3 push.py
Traceback (most recent call last):
  File "push.py", line 8, in <module>
    push("127.0.0.1", 18159, "vlan 10\n")
  File "push.py", line 4, in push
    with socket.create_connection(
  File "/usr/lib/python3.13/socket.py", line 868
    raise exceptions[0]
ConnectionRefusedError: [Errno 111] Connection refused
```

- Expect it and handle it: ==exception handling== with `try` / `except ConnectionRefusedError`, a one-line message, and a non-zero ==exit code== (`sys.exit(2)`)
  - The pipeline still fails, but the log says why: `push failed: [Errno 111] Connection refused`

| Error | Usual cause |
|---|---|
| `ConnectionRefusedError` | service down or wrong port |
| `TimeoutError` | firewall dropping traffic, wrong IP |
| `FileNotFoundError` | wrong path or working directory |
| `PermissionError` | file mode, missing `sudo` |
| `KeyError` | field missing from a dict or API reply |
| `TypeError: 'NoneType'...` | a lookup returned nothing |

### Bash: unset variables and set -u
- Bash expands an unset variable to an empty string and keeps going
  - `rm -rf "$STAGE_DIR/"*` with `STAGE_DIR` unset becomes `rm -rf /*`
- ==set -u== (part of `set -euo pipefail`) turns that into an ==unbound variable== runtime error that stops the script

```bash label="banner.sh"
#!/usr/bin/env bash
set -euo pipefail
site="CLT-01"
echo "site: ${site}"
echo "contact: ${site_contact}"
echo "done"
```

```console label="Terminal"
$ bash banner.sh
site: CLT-01
banner.sh: line 5: site_contact: unbound variable
```

- Without `-u` the same script prints `contact: ` with nothing after it, then `done`, and exits 0
- `shellcheck` warns before you run it: "SC2154 (warning): site_contact is referenced but not assigned."
- Make intent explicit: `${site_contact:-noc@example.com}` for a default, `${site_contact:?must be set}` to require it
- `bash -n` is the syntax check: an `if` with no `fi` reports `syntax error: unexpected end of file`

### Terraform: validate before plan
- Referencing a variable that was never declared is an ==undeclared input variable==, caught by `terraform validate`

```console label="Terminal"
$ terraform validate

Error: Reference to undeclared input variable

  on main.tf line 7, in resource "local_file" "motd":
   7:   content  = "Welcome to ${var.host_name}\n"

An input variable with the name "host_name" has not been declared. Did you
mean "hostname"?
```

- A declared variable with no value is a missing ==required variable== ("Error: No value for required variable" at `plan`)
  - Supply it with `-var`, a `.tfvars` file, `TF_VAR_hostname`, or a `default`
- A missing `}` is a syntax error: "Error: Unclosed configuration block"
- `validate` proves the code is well formed, not that it will work
  - A `local_file` path under `/proc` passes `validate` and `plan`, then `apply` fails at run time with "Error: Create local file error ... mkdir /proc/motd: no such file or directory"

### Ansible: undefined variables at run time
- `--syntax-check` parses the YAML and play structure only; ==templated values are not evaluated== until the task runs, so this passes the check and fails on the target

```yaml label="motd.yml (task)"
- name: Write the banner
  ansible.builtin.copy:
    dest: "{{ playbook_dir }}/motd"
    content: "{{ site }} {{ site_contact }}\n"
    mode: "0644"
```

```console label="ansible-playbook motd.yml (trimmed)"
TASK [Write the banner] ***********************
[ERROR]: Task failed: ...
<<< caused by >>>

Error while resolving value for 'content': 'site_contact' is undefined
Origin: motd.yml:11:18
11         content: "{{ site }} {{ site_contact }}\n"
                    ^ column 18

fatal: [localhost]: FAILED! => ...
```

- Fixes
  - Define it where it belongs: play `vars`, `group_vars/`, `host_vars/`, role `defaults/`, or `-e`
  - Fall back with the ==default filter==: `{{ site_contact | default('noc@example.com') }}`
  - Fail early with a clear message: `{{ site_contact | mandatory }}`

:::exam
- "The script fails before any output appears" points to a syntax error. "It worked on the lab switch but fails on the production switch" points to a runtime error caused by the environment.
- Know where each tool reports an undefined variable: Python raises `NameError` and Ansible reports `'x' is undefined` at run time; Bash prints `unbound variable` only with `set -u`; Terraform fails `validate` with "Reference to undeclared input variable."
:::
