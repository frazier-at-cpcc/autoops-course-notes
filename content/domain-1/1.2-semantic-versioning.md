### Version numbers that carry meaning
- ==Semantic versioning== (SemVer): `MAJOR.MINOR.PATCH`
  - Defined at semver.org; the current specification is 2.0.0
  - The number tells consumers whether an upgrade is safe before they read a single release note
- Applies to anything other people depend on
  - Ansible roles and collections, Terraform modules, internal Python packages, container images, APIs

:::figure semver-anatomy.svg | Every part has a job. Only MAJOR, MINOR, PATCH, and the pre-release label affect which version is "newer."

- ==MAJOR==: an incompatible, breaking change
  - A playbook variable is renamed, an API field is removed, a default changes behavior
- ==MINOR==: new functionality that is backward compatible
  - A new optional variable with a sensible default
- ==PATCH==: a backward-compatible bug fix
- Bumping one number resets everything to its right
  - `1.4.2` to `1.4.3` (fix), to `1.5.0` (feature), to `2.0.0` (break)
- `0.y.z` is initial development
  - Anything may change at any time; the public interface is not stable yet
- Once a version is released, its contents never change
  - Fixing it means releasing a new version

### Major vs. minor releases
- A ==major release== asks consumers to do work
  - Read the upgrade notes, change their code or inventory, test
  - Schedule it; announce it; support the previous major for a while
- A ==minor release== is safe to take
  - New capabilities appear; nothing existing breaks
- Patch releases should be taken quickly
  - Especially security fixes

| Change to a Terraform module | Bump |
|---|---|
| Rename a required input variable | Major |
| Change a default that alters existing resources | Major |
| Add an optional input with a default | Minor |
| Add a new output | Minor |
| Fix a wrong tag value on a resource | Patch |
| Correct a typo in the README only | None, or patch |

### Pre-release versions
- A hyphen and identifiers after the patch number
  - `2.0.0-alpha`, `2.0.0-beta.2`, `2.0.0-rc.1` (release candidate)
- A pre-release ranks ==below== its final release
  - `1.9.0` < `2.0.0-alpha` < `2.0.0-beta.2` < `2.0.0-rc.1` < `2.0.0`
- Signals "not yet stable": deploy to test and staging, not production
- ==Build metadata== follows a plus sign: `2.0.0+build.517`
  - Records the build or commit; ignored when comparing versions

### Filtering techniques
- ==Version constraints== filter which versions a tool may install
  - Written in `package.json`, `requirements.txt`, Ansible `requirements.yml`, Terraform `required_providers`

| Constraint | Accepts | Rejects |
|---|---|---|
| `1.2.3` | exactly 1.2.3 | everything else |
| `^1.2.3` | `>=1.2.3 <2.0.0` | 2.0.0 and up |
| `~1.2.3` | `>=1.2.3 <1.3.0` | 1.3.0 and up |
| `1.x` | any 1.y.z | 2.0.0 and up |
| `>=1.4.0 <2.0.0` | that range | outside it |
| Terraform `~> 1.2` | `>=1.2 <2.0` | 2.0 and up |
| Terraform `~> 1.2.0` | `>=1.2.0 <1.3.0` | 1.3.0 and up |

- Caret (`^`) means "take new minors and patches"; tilde (`~`) means "patches only"
- Pre-releases are excluded unless you ask for them
  - `^1.2.3` does not match `1.3.0-beta.1`
- `^0.2.3` stays inside `0.2.x`, because in 0.y.z every minor may break

```console label="npm semver CLI"
$ npx semver -r '^1.2.3' 1.2.9 1.9.0 2.0.0 1.3.0-beta.1
1.2.9
1.9.0
$ npx semver -i premajor --preid rc 1.4.2
2.0.0-rc.0
```

### Filtering versions in Git
- Releases are marked with ==tags==
  - `git tag -a v1.0.0 -m "First stable release"` creates an annotated tag (author, date, message)
  - `git tag v1.0.0` creates a lightweight tag (just a pointer)
- `git tag -l 'v1.*'`: list tags matching a pattern
- `git describe --tags --abbrev=0`: the most recent tag reachable from HEAD
- Sort by version, not alphabetically
  - Alphabetical order puts `v1.10.0` before `v1.2.0`

```console label="Terminal"
$ git tag -l --sort=-v:refname
v2.0.0-rc.1
v2.0.0
v1.10.0
$ git config versionsort.suffix -
$ git tag -l --sort=-v:refname
v2.0.0
v2.0.0-rc.1
v1.10.0
```

- Without `versionsort.suffix`, Git ranks `v2.0.0-rc.1` above `v2.0.0`
  - `sort -V` has the same blind spot
- Stable releases only: `git tag -l | grep -E '^v[0-9]+\.[0-9]+\.[0-9]+$'`

:::exam
- Given a description of a change, pick the bump: breaking is major, new compatible feature is minor, fix is patch. Watch for "removed" or "renamed" in the scenario; that is a major release.
- `2.0.0-rc.1` is older than `2.0.0`. A distractor will treat the extra characters as "newer."
- Caret allows minors; tilde allows only patches.
:::
