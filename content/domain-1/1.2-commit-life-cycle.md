### From edit to remote
- Between editing a file and the change reaching the team, Git gives you places to run checks automatically
- Checks that run early are cheap
  - A lint error caught before commit costs seconds
  - The same error caught by the pipeline costs a pipeline run and a context switch

:::figure wide commit-life-cycle.svg | Client-side hooks give fast feedback. Anything that must never be skipped is enforced again on the server or in CI.

### Hooks
- A ==hook== is a script Git runs automatically at a point in the life cycle
  - Stored in `.git/hooks/`, named for the event, and executable
  - A ==non-zero exit code== stops the action
- Client-side hooks

| Hook | Runs | Typical job |
|---|---|---|
| `pre-commit` | before the commit is created | format, lint, scan for secrets |
| `prepare-commit-msg` | before the editor opens | insert a ticket ID or template |
| `commit-msg` | after the message is written | enforce the message format |
| `post-commit` | after the commit | notifications |
| `pre-push` | before the push sends anything | run quick tests |

- Server-side hooks: `pre-receive`, `update`, `post-receive`
  - Run on the Git server; the client cannot skip them
- Client hooks are ==not enforced==
  - `git commit --no-verify` skips `pre-commit` and `commit-msg`
  - Repeat any check that matters in the CI pipeline
- `.git/hooks/` is not part of the repository
  - Share hooks with a tracked folder: `git config core.hooksPath .githooks`
  - Or use the ==pre-commit framework==: one tracked `.pre-commit-config.yaml`, then `pre-commit install`

```sh label=".git/hooks/commit-msg"
#!/bin/sh
# Enforce Conventional Commits: type(optional scope): summary
pattern='^(feat|fix|docs|chore|refactor|test|ci)(\([a-z0-9-]+\))?!?: .{1,72}$'
if ! head -1 "$1" | grep -Eq "$pattern"; then
  echo "commit-msg: use 'type(scope): summary'" >&2
  exit 1
fi
```

### Formatting
- A ==formatter== rewrites code into one consistent style
  - Python: `black`, `ruff format`; YAML, JSON, Markdown: `prettier`; Terraform: `terraform fmt`; shell: `shfmt`
- Ends style arguments in code review
- Keeps diffs about real changes, not whitespace
- Two modes
  - Fix mode rewrites files (on your machine, in `pre-commit`)
  - ==Check mode== only reports and fails (in CI): `black --check`, `terraform fmt -check`

### Linting
- A ==linter== reads code without running it and flags likely bugs and risky patterns
  - Python: `ruff`, `flake8`, `pylint`; shell: `shellcheck`; YAML: `yamllint`; Ansible: `ansible-lint`; Terraform: `tflint`
- Catches unused imports, undefined variables, unquoted shell variables, invalid YAML
- Formatting changes how code looks; linting finds problems in what it does
- A formatter hook reports ==Failed== when it rewrites a file
  - Nothing is broken: review the change, `git add` it, and commit again

```console label="pre-commit run --all-files"
$ pre-commit run --all-files
trim trailing whitespace.................Passed
check yaml...............................Passed
detect private key.......................Failed
ruff.....................................Failed
ruff-format..............................Failed
```

```yaml label=".pre-commit-config.yaml"
repos:
  - repo: https://github.com/pre-commit/pre-commit-hooks
    rev: v5.0.0
    hooks:
      - id: trailing-whitespace
      - id: check-yaml
      - id: detect-private-key
  - repo: https://github.com/astral-sh/ruff-pre-commit
    rev: v0.6.9
    hooks:
      - id: ruff          # lint
      - id: ruff-format   # format
```

### Detecting sensitive data
- Once a secret is committed, it is in history
  - A later commit that deletes the line does not remove it from earlier commits
  - Treat a pushed secret as compromised: ==rotate the credential== first, then clean history
- Prevent it at the earliest point
  - `.gitignore` for `.env`, `*.pem`, `terraform.tfstate`
  - A `pre-commit` scanner: `gitleaks`, `git-secrets`, `detect-secrets`, `trufflehog`
  - Scanners match known key formats (an AWS access key ID starts with `AKIA`) and high-entropy strings
- Enforce it on the server too
  - Platform secret scanning and push protection reject the push

```sh label=".git/hooks/pre-commit"
#!/bin/sh
# Block commits that stage something shaped like an AWS access key ID
if git diff --cached -U0 | grep -E '^\+.*AKIA[0-9A-Z]{16}' >/dev/null; then
  echo "pre-commit: possible AWS access key in staged changes" >&2
  exit 1
fi
```

### Comments
- The ==commit message== is the comment on a change
  - Future you reads it at 2 a.m. during an outage
- First line: a summary in the imperative mood, about 50 characters, 72 at most
  - "fix(dns): correct TTL on internal zone", not "fixed stuff"
- Blank line, then a body explaining why
- ==Conventional Commits==: `type(scope): summary`
  - Types: `feat`, `fix`, `docs`, `chore`, `refactor`, `test`, `ci`
  - `!` after the type, or a `BREAKING CHANGE:` footer, marks a breaking change
  - Tools read the history and pick the next version: `fix` is a patch, `feat` is a minor, breaking is a major
- Code comments explain why, not what
  - Never leave a credential in a commented-out line

:::exam
- Hooks are scripts in `.git/hooks/`, and a non-zero exit blocks the action. `pre-commit` is where formatting, linting, and secret scanning run; `commit-msg` checks the message.
- Client-side hooks can be bypassed with `--no-verify`, so mandatory checks belong in CI or a server-side hook.
- If a secret reached the remote, the first step is revoking or rotating it, not rewriting history.
:::
