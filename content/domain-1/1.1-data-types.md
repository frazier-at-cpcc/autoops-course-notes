### Primitive data types
- A data type tells the language what a value is and what you can do with it
- ==Primitive== types hold a single value
  - ==String==: text, such as a hostname or an interface name
  - ==Integer==: whole numbers, such as a VLAN ID or a port
  - ==Float==: numbers with a fraction, such as a CPU load of `0.73`
  - ==Boolean==: true or false, such as `stp_enabled`
  - Null: "no value," such as an interface with no uplink
- Collections hold many values
  - List (array): ordered values, such as `[10, 20, 30]`
  - Dictionary (map, object): key and value pairs, such as `{"hostname": "core-sw1"}`

:::wide
| Type | Python | JSON | YAML |
|---|---|---|---|
| String | `"core-sw1"` (`str`) | `"core-sw1"` | `core-sw1` or `"core-sw1"` |
| Integer | `9216` (`int`) | `9216` | `9216` |
| Float | `0.73` (`float`) | `0.73` | `0.73` |
| Boolean | `True` / `False` | `true` / `false` | `true` / `false` |
| Null | `None` | `null` | `null` or `~` |
| List | `[10, 20]` | `[10, 20]` | `- 10` on its own line, or `[10, 20]` |
| Dictionary | `{"mtu": 9216}` | `{"mtu": 9216}` | `mtu: 9216` |
:::

- Python is dynamically but strongly typed: mixing types needs a conversion such as `int()` or `str()`
- Bash has no real types; every value is a string until `$(( ))` treats it as a number

```console label="Terminal"
$ python3 -c 'print("10" + 1)'
TypeError: can only concatenate str (not "int") to str
$ python3 -c 'print(int("10") + 1)'
11
```

### JavaScript Object Notation (JSON)
- ==JSON== is the format most REST APIs send and receive
  - Also `package.json`, Terraform state, cloud CLI output
- Objects in braces `{}`, arrays in brackets `[]`, `"key": value` pairs separated by commas
- The rules are strict
  - Keys and strings use ==double quotes== only
  - ==No trailing commas== after the last item
  - ==No comments==
  - `true`, `false`, and `null` are lowercase
- Whitespace and indentation do not matter

```json label="switch.json"
{
  "hostname": "core-sw1",
  "mgmt_ip": "10.0.0.11",
  "vlans": [10, 20, 30],
  "stp_enabled": true,
  "uplink": null,
  "mtu": 9216
}
```

- One stray comma breaks the whole document

```console label="Terminal"
$ echo '{"vlan": 10,}' | jq .
jq: parse error: Expected another key-value pair at line 1, column 13
```

### YAML Ain't Markup Language (YAML)
- ==YAML== is the format people write by hand
  - Ansible playbooks, Kubernetes manifests, Docker Compose, CI pipelines
- Structure comes from ==indentation==: spaces only, never tabs
- `key: value` makes a mapping; `- item` makes a list entry; `#` starts a comment
- Strings usually need no quotes
- `---` starts a new document; `|` keeps line breaks in a block of text (a login banner)
- YAML 1.2 is a superset of JSON: a YAML parser can read a JSON file

```yaml label="switch.yaml"
# core switch facts
hostname: core-sw1
mgmt_ip: 10.0.0.11
vlans:
  - 10
  - 20
  - 30
stp_enabled: true
uplink: null
mtu: 9216
```

### The same data in both formats
- `switch.json` and `switch.yaml` above load into the ==same Python dictionary==
  - JSON for machine-to-machine traffic; YAML for files people edit and review

```python label="load.py"
import json
import yaml   # PyYAML: pip install PyYAML

with open("switch.json") as f:
    from_json = json.load(f)
with open("switch.yaml") as f:
    from_yaml = yaml.safe_load(f)

print("same data:", from_json == from_yaml)
for key, value in from_yaml.items():
    print(f"{key:<12} {type(value).__name__}")
```

```console label="Terminal"
$ python3 load.py
same data: True
hostname     str
mgmt_ip      str
vlans        list
stp_enabled  bool
uplink       NoneType
mtu          int
```

- `mgmt_ip` is a string; neither format has an IP address type
- Use `yaml.safe_load()` (the ==safe loader==); the full loader can build arbitrary Python objects from untrusted input
- `yq -o json switch.yaml` (Go `yq`) converts YAML to JSON for `jq`

### YAML gotchas
- `show.py` prints each key with the value and type PyYAML produced

```python label="show.py"
import sys
import yaml

with open(sys.argv[1]) as f:
    data = yaml.safe_load(f)
for key, value in data.items():
    kind = type(value).__name__
    print(f"{key:<10} {value!r} ({kind})")
```

- Wrong indentation can change the structure with no error: one extra space merges two list items

```yaml label="vlans.yaml"
vlans:
  - 10
   - 20
```

```console label="Terminal"
$ python3 show.py vlans.yaml
vlans      ['10 - 20'] (list)
```

- A tab used for indentation fails outright: `found character '\t' that cannot start any token`
- Unquoted values are ==type-guessed== by the parser
  - YAML 1.1 parsers turn `yes`, `no`, `on`, `off` into booleans
  - The ==Norway problem==: country code `NO` becomes `false`
  - `1.10` is a float, which prints as `1.1`
  - YAML 1.1 reads `22:22` as base-60 arithmetic
- PyYAML (6.0.3, the parser Ansible uses) follows YAML 1.1

```yaml label="site.yaml"
country: NO
vlan_name: off
version: 1.10
ssh_map: 22:22
quoted: "NO"
```

```console label="Terminal"
$ python3 show.py site.yaml
country    False (bool)
vlan_name  False (bool)
version    1.1 (float)
ssh_map    1342 (int)
quoted     'NO' (str)
```

- YAML 1.2 parsers such as `ruamel.yaml` keep `NO`, `off`, and `22:22` as strings
  - `1.10` is still a float in every version
- The fix is the same everywhere: ==quote anything that must stay a string==
  - Country codes, version numbers, port mappings, leading-zero IDs like `"0042"`
- `yamllint` warns on `yes`/`no`/`on`/`off` (its `truthy` rule) and bad indentation

:::exam
- Given a JSON snippet that fails to parse, look for a trailing comma, single quotes, a comment, or capitalized `True`. Those are Python habits that JSON rejects.
- Given YAML that "loads the wrong value," suspect indentation first, then an unquoted value that the parser converted to a boolean or number.
- Know which primitive each value becomes: `"10"` is a string, `10` is an integer, `true` is a Boolean, `null` is null.
:::
