### Parse before you deploy
- A config file with one bad character can stop a service, fail a playbook, or push half a change
  - The parser stops at the first error and reports a line and column
  - That position is where the parser gave up, which is often the line after the real mistake
- ==Validate== every config file in the pipeline, before anything restarts
  - One small checker covers all three formats used below

```python label="check-config.py"
#!/usr/bin/env python3
"""Parse INI, YAML, or JSON files; report the error."""
import configparser, json, sys
import yaml  # PyYAML

status = 0
for path in sys.argv[1:]:
    try:
        with open(path) as f:
            if path.endswith(".ini"):
                cp = configparser.ConfigParser()
                cp.read_file(f)
                # reading each value expands %(name)s references
                [dict(cp[s]) for s in cp.sections()]
            elif path.endswith((".yml", ".yaml")):
                yaml.safe_load(f)
            else:
                json.load(f)
        print(f"{path}: OK")
    except Exception as e:
        print(f"{path}: {type(e).__name__}: {e}")
        status = 1
sys.exit(status)
```

- Format-specific tools: ==yamllint== for YAML, `jq empty` or `python3 -m json.tool` for JSON, and the application's own test mode (`nginx -t`, `ansible-playbook --syntax-check`)

### INI
- ==Sections== in brackets, then `key = value` (or `key: value`) lines
  - Comments start with `;` or `#` on their own line
  - Flat: sections cannot nest
  - Every value is a string; the program converts it (`getint`, `getboolean`)
- Seen in `ansible.cfg`, Ansible's INI-style inventory, `.gitconfig`, `php.ini`, and systemd unit files (a close cousin)
- An inline comment is not a comment to `configparser` by default
  - `timeout = 10 ; seconds` stores the string `10 ; seconds`, and `getint` then fails

```ini label="agent.ini"
; inventory sync agent
[api]
url = https://inv.lab.test:8443
token = s3cr3t
timeout = 10

[logging]
level = info
file = /var/log/invsync/%(level)s.log
```

- `%(level)s` is ==interpolation==: Python's `configparser` swaps in another key's value
  - A literal `%` must be written `%%`
- Four broken files and what `configparser` says about each

```console label="Terminal"
$ cat noeq.ini
[api]
url = https://inv.lab.test:8443
timeout = 10
retries 3
```

:::wide

- `nohdr.ini`: a key before the first `[section]`
- `noeq.ini`: a line with no `=` or `:`
- `dup.ini`: `timeout` set twice in one section (strict mode, the default)
- `pct.ini`: a password containing `%`; write `P@ss%%word`

### YAML
- Structure comes from ==indentation==: spaces only, never tabs
  - Two spaces per level is the convention; it just has to be consistent
- `key: value` needs a space after the colon
- A list item starts with `- `
- Quote strings that contain `: `, start with a special character (`{`, `[`, `*`, `&`, `!`, `%`, `@`), or look like another type
- `---` marks the start of a document; `#` starts a comment
- Ansible playbooks and inventories, Kubernetes manifests, Docker Compose, GitHub Actions and GitLab CI pipelines

```yaml label="vlans.yml"
---
site: charlotte-dc1
vlans:
  - id: 10
    name: users
  - id: 20
    name: servers
    description: "Rack 4: east wing"
```

```console label="Terminal"
$ cat -A tab.yml | sed -n 4p
^Iname: users$
```

- `cat -A` shows a tab as `^I`; most editors hide it

:::wide
```console label="Terminal"
$ ./check-config.py tab.yml colon.yml indent.yml nospace.yml
tab.yml: ScannerError: while scanning for the next token
found character '\t' that cannot start any token
  in "tab.yml", line 4, column 1
colon.yml: ScannerError: mapping values are not allowed here
  in "colon.yml", line 4, column 24
indent.yml: ParserError: while parsing a block collection
  in "indent.yml", line 3, column 3
expected <block end>, but found '<block mapping start>'
  in "indent.yml", line 6, column 4
nospace.yml: ScannerError: mapping values are not allowed here
  in "nospace.yml", line 4, column 12
```
:::

- `colon.yml`: `description: Rack 4: east wing` without quotes; the second `: ` looks like another key
- `indent.yml`: `name:` indented three spaces under a list item whose keys sit at four
- `nospace.yml`: `hostname:core-sw1` has no space after the colon, so it is a plain string, not a key; the error lands on the next line
- Valid YAML can still be wrong: PyYAML follows YAML 1.1 type rules

```yaml label="site.yml"
---
site:
  country: NO
  file_mode: 0644
  os_version: 7.10
  lldp: on
  vlan:
    name: users
    name: staff
```

:::wide
```console label="Terminal"
$ python3 -c "import yaml; print(yaml.safe_load(open('site.yml')))"
{'site': {'country': False, 'file_mode': 420, 'os_version': 7.1, 'lldp': True, 'vlan': {'name': 'staff'}}}
$ yamllint site.yml
site.yml
  3:12      warning  truthy value should be one of [false, true]  (truthy)
  6:9       warning  truthy value should be one of [false, true]  (truthy)
  9:5       error    duplication of key "name" in mapping  (key-duplicates)
```
:::

- Norway became `False`, the file mode became octal `420`, version `7.10` became `7.1`, and the first `name` silently vanished
  - Fix: quote them (`"NO"`, `"0644"`, `"7.10"`) and run ==yamllint== in CI, which catches what the parser accepts
  - Ansible loads YAML with PyYAML, which is why its docs tell you to quote file modes: `mode: "0644"`

### JSON
- Objects `{}` of `"key": value` pairs and arrays `[]`, separated by commas
- Strict rules, and each breaks a parse
  - Keys and strings in ==double quotes== only
  - No ==trailing comma== after the last item
  - No comments
  - Lowercase `true`, `false`, `null`
- REST API bodies, `package.json`, AWS IAM policies, Terraform `.tf.json`, VS Code settings

:::wide
| Mistake | Example | `jq` reports | `python3 -m json.tool` reports |
|---|---|---|---|
| Trailing comma | `{"id": 10, "name": "users"},` then `]` | `Expected another array element at line 4, column 3` | `Illegal trailing comma before end of array: line 3 column 32 (char 46)` |
| Single quotes | `'id': 10` | `Invalid numeric literal at line 2, column 7` | `Expecting property name enclosed in double quotes: line 2 column 3 (char 4)` |
| Comment | `// core VLAN` | `Invalid numeric literal at line 2, column 5` | `Expecting property name enclosed in double quotes: line 2 column 3 (char 4)` |
| Missing comma | `"id": 10` then `"name": ...` | `Expected separator between values at line 3, column 8` | `Expecting ',' delimiter: line 3 column 3 (char 15)` |
| Capital boolean | `"voice": False` | `Invalid numeric literal at line 4, column 0` | `Expecting value: line 3 column 12 (char 25)` |
:::

- The two tools disagree on positions; neither always points at the bad character
- The trailing-comma message is new in Python 3.13; older versions say `Expecting value` or `Expecting property name`
- `jq empty` prints nothing and exits `0` on valid JSON, so it works as a CI gate

```console label="Terminal"
$ jq empty vlans.json && echo valid
valid
```

- JSON is valid YAML (YAML 1.2 is a superset), so a YAML parser reads a JSON file; the reverse does not work

### Side by side

:::wide
| | INI | YAML | JSON |
|---|---|---|---|
| Structure | Sections and `key = value` | Indentation, `key: value`, `- item` | Braces, brackets, commas |
| Nesting | One level (sections) | Unlimited | Unlimited |
| Data types | Strings only | Strings, numbers, booleans, null, lists, maps (inferred) | Strings, numbers, `true`/`false`, `null`, arrays, objects |
| Comments | `;` or `#` | `#` | None |
| Whitespace matters | No | Yes: indentation is the structure | No |
| Classic mistake | Duplicate key, missing section | Tab, bad indent, unquoted `: ` | Trailing comma, single quotes |
| Check with | `configparser`, the app's own loader | `yamllint`, `yaml.safe_load` | `jq empty`, `python3 -m json.tool` |
:::

:::exam
- Expect a short file and a question about why it fails: a tab or uneven indent in YAML, a trailing comma or single quotes in JSON, a key outside any section in INI.
- "Which format allows comments?" INI and YAML yes, JSON no. "Which uses indentation for structure?" YAML.
- A YAML file that parses but gives the wrong value (`NO` to false, `0644` to 420) is fixed by quoting; a linter such as `yamllint` flags it.
:::
