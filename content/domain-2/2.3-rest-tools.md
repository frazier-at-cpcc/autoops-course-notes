### The lab API
- Every example on these pages ran against a small VLAN inventory API
  - Python standard library only, started by `tests/2.3-rest-api.sh` on port 18300
  - `GET` and `POST` on `/api/v1/vlans`; `GET`, `PUT`, `PATCH`, `DELETE` on `/api/v1/vlans/{id}`
  - Bearer tokens: `s3cr3t-admin` can write, `s3cr3t-viewer` can only read
- Put the parts you repeat in shell variables
  - Shorter commands, and the token is typed once

```console label="Terminal"
$ API=http://127.0.0.1:18300/api/v1
$ AUTH="Authorization: Bearer s3cr3t-admin"
$ CT="Content-Type: application/json"
```

### curl options for API work
- ==curl== sends one request, prints the response body, and exits
  - Installed nearly everywhere, including Windows 10 and later as `curl.exe`
  - The default method is `GET`

| Option | What it does |
|---|---|
| `-X PATCH` | Sets the method |
| `-H "Name: value"` | Adds a request header (repeatable) |
| `-d '{...}'`, `-d @file` | Sends a body; implies `POST` |
| `--json '{...}'` | Body plus JSON headers (curl 7.82+) |
| `-i` | Prints response headers too |
| `-v` | Shows both sides' headers and TLS |
| `-s`, `-S` | No progress meter; still show errors |
| `-f` | Exit code 22 on HTTP 400 or higher |
| `-o file` | Saves the body to a file |
| `-w '%{http_code}'` | Prints the status code |
| `-L` | Follows `3XX` redirects |
| `-u user:pass` | Basic authentication |
| `-k` | Skips certificate checks: lab only |

- `-d` alone sends `Content-Type: application/x-www-form-urlencoded`
  - A JSON API answers that with `415 Unsupported Media Type`; always add the `Content-Type` header (or use `--json`)

### A full CRUD session with curl

```json label="vlan30.json"
{
  "id": 30,
  "name": "voice",
  "description": "IP phones"
}
```

- ==Create== with `POST`, and three ways the create can be refused (headers trimmed)

:::wide
```console label="Terminal"
$ curl -si -H "$AUTH" -H "$CT" -d @vlan30.json $API/vlans
HTTP/1.1 201 Created
Location: /api/v1/vlans/30
Content-Type: application/json

{"id": 30, "name": "voice", "description": "IP phones"}
$ curl -si -H "$AUTH" -H "$CT" -d @vlan30.json $API/vlans
HTTP/1.1 409 Conflict

{"error": "VLAN 30 already exists"}
$ curl -si -H "$AUTH" -d @vlan30.json $API/vlans
HTTP/1.1 415 Unsupported Media Type

{"error": "send Content-Type: application/json"}
$ curl -si -H "$AUTH" -H "$CT" -d '{"id": 5000, "name": "lab"}' $API/vlans
HTTP/1.1 422 Unprocessable Content

{"error": "validation failed", "fields": {"id": "must be 1-4094"}}
```
:::

- ==Read==, ==update==, and ==delete==

:::wide
```console label="Terminal"
$ curl -s -H "$AUTH" $API/vlans | jq -r '.[].name'
users
servers
voice
$ curl -s -X PUT -H "$AUTH" -H "$CT" -d '{"name": "voip"}' $API/vlans/30
{"id": 30, "name": "voip"}
$ curl -s -X PATCH -H "$AUTH" -H "$CT" -d '{"description": "Desk phones"}' $API/vlans/30
{"id": 30, "name": "voip", "description": "Desk phones"}
$ curl -si -X DELETE -H "$AUTH" $API/vlans/30
HTTP/1.1 204 No Content
$ curl -si -X DELETE -H "$AUTH" $API/vlans/30
HTTP/1.1 404 Not Found
```
:::

- The `PUT` dropped the description; the `PATCH` added one back and kept the name
- Inside the `-d` string, JSON needs double quotes, so wrap the whole string in single quotes for the shell

### curl in scripts
- By default curl exits `0` for any HTTP response, even a `500`
  - ==-f== (`--fail`) is the fix
  - It turns `4XX` and `5XX` into exit code `22`, so `set -e` and CI jobs notice

```console label="Terminal"
$ curl -sSf -H "$AUTH" $API/vlans/30
curl: (22) The requested URL returned error: 404
$ curl -sf -H "$AUTH" $API/vlans/30 || echo "exit=$?"
exit=22
```

- To branch on the exact code, capture it with `-w` and discard the body

```bash label="vlan-exists.sh"
#!/usr/bin/env bash
# Exit 0 if VLAN $1 exists, 1 if not, 2 on anything else
code=$(curl -s -o /dev/null -w '%{http_code}' \
  -H "$AUTH" "$API/vlans/$1")
case $code in
  200) echo "VLAN $1 present" ;;
  404) echo "VLAN $1 missing"; exit 1 ;;
  *)   echo "unexpected HTTP $code"; exit 2 ;;
esac
```

```console label="Terminal"
$ ./vlan-exists.sh 10
VLAN 10 present
$ ./vlan-exists.sh 30; echo "exit=$?"
VLAN 30 missing
exit=1
$ AUTH="Authorization: Bearer typo" ./vlan-exists.sh 10
unexpected HTTP 401
```

- ==jq== slices the JSON that comes back

```console label="Terminal"
$ curl -s -H "$AUTH" $API/vlans -o all.json
$ jq -r '.[] | "\(.id) \(.name)"' all.json
10 users
20 servers
31 voice2
$ jq 'map(select(.id >= 20)) | length' all.json
2
```

### wget
- ==wget== is a downloader first
  - Saves the body to a file named after the URL; `-O-` writes to the terminal instead
  - Follows redirects on its own (curl needs `-L`)
  - Exit code `8` means the server answered with an error status
- Same API, wget flags

:::wide
```console label="Terminal"
$ wget -qO- --header "$AUTH" $API/vlans/10
{"id": 10, "name": "users", "description": "Staff desktops"}
$ wget -qO- --header "$AUTH" --header "$CT" --post-data '{"id": 60, "name": "cameras"}' $API/vlans
{"id": 60, "name": "cameras"}
$ wget -qO- --method=PATCH --header "$AUTH" --header "$CT" --body-data '{"name": "cctv"}' $API/vlans/60
{"id": 60, "name": "cctv"}
$ wget -qS -O /dev/null --method=DELETE --header "$AUTH" $API/vlans/60
  HTTP/1.1 204 No Content
$ wget -q --header "$AUTH" $API/vlans/60; echo "exit=$?"
exit=8
```
:::

- `--post-data` sends `POST`; any other method needs `--method` plus `--body-data`
- `-S` prints the response headers (to stderr)
- Reach for curl when you are working an API; wget fits "fetch this file" jobs such as pulling an image or a config template

### Postman and Newman
- ==Postman== is a graphical API client: build a request, send it, save it, share it
- A ==collection== is a saved, ordered set of requests
  - Each request can carry scripts written in JavaScript against the `pm` object
  - Pre-request scripts run first (build a timestamp, fetch a token); post-response scripts hold the tests
  - Set auth once on the collection; requests inherit it
  - Exports to JSON (collection format v2.1), so it can live in Git
- An ==environment== is a named set of ==variables== for one target: lab, staging, production
  - Requests use `{{baseUrl}}` and `{{token}}`; pick another environment and the same collection hits another system
  - Scopes from broadest to narrowest: global, collection, environment, data (a CSV or JSON file feeding a run), local; the narrowest one wins

```json label="lab.json"
{
  "name": "lab",
  "values": [
    { "key": "baseUrl",
      "value": "http://127.0.0.1:18300/api/v1" },
    { "key": "token", "value": "s3cr3t-admin" }
  ]
}
```

```javascript label="Create VLAN: post-response script"
pm.test('status is 201', () =>
  pm.response.to.have.status(201));
pm.test('Location header set', () =>
  pm.response.to.have.header('Location'));
```

- ==Newman== runs an exported collection from the command line (`npm install -g newman`)
  - Exit code `0` when every test passes, `1` when any fails, so a CI job can gate on it
  - Postman also publishes its own runner, the Postman CLI (`postman collection run`)

:::wide
```console label="Terminal"
$ newman run vlans.json -e lab.json --disable-unicode
  POST http://127.0.0.1:18300/api/v1/vlans [201 Created, 245B, 50ms]
  Pass  status is 201
  Pass  Location header set
  GET http://127.0.0.1:18300/api/v1/vlans/70 [200 OK, 234B, 4ms]
  Pass  name is printers
  PATCH http://127.0.0.1:18300/api/v1/vlans/70 [200 OK, 209B, 46ms]
  Pass  status is 200
  DELETE http://127.0.0.1:18300/api/v1/vlans/70 [204 No Content, 156B, 2ms]
  Pass  status is 204
|              assertions |                5 |                0 |
$ newman run vlans.json -e ro.json --disable-unicode --color off
  POST http://127.0.0.1:18300/api/v1/vlans [403 Forbidden, 220B, 26ms]
  1. status is 201
 1.  AssertionError  status is 201
                     expected response to have status code 201 but got 403
```
:::

- Same collection, environment with the read-only token: every write fails and the run exits `1`

:::exam
- Match flags to jobs: `-X` sets the method, `-H` adds a header, `-d` sends a body, `-i` shows response headers, `-L` follows redirects, `-k` ignores certificate errors (a red flag in any production answer).
- Postman environment variables let one collection target lab or production unchanged. Newman, or the Postman CLI, runs that collection in a pipeline and fails the job on a failed test.
- A JSON body sent without `Content-Type: application/json` is a common distractor; expect `415` or `400` from the API.
:::
