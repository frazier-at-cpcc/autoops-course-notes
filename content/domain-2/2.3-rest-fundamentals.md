### What makes an API RESTful
- ==REST== (Representational State Transfer) is an architectural style for web APIs
  - Not a protocol or a product: plain HTTP or HTTPS, usually with JSON bodies
  - A ==RESTful== API follows its constraints
- Everything is a ==resource== with its own URI
  - Collection: `/api/v1/vlans`; one item: `/api/v1/vlans/30`
  - Nouns in the path, the action in the method: `DELETE /vlans/30`, not `/deleteVlan?id=30`
- ==Stateless==: each request carries everything the server needs
  - The token rides in a header on every call; there is no session to lose
  - Any node behind a load balancer can answer any request
- The other constraints
  - Client-server split, cacheable responses, a uniform interface
  - Layered system: proxies and gateways in the path are invisible to the client
- An ==endpoint== is a base URL plus a resource path
  - The version usually sits in the base URL: `/api/v1/`
  - A query string filters a collection: `/api/v1/vlans?name=voice`
- Where REST shows up in network automation
  - NetBox or Nautobot as the source of truth, the Meraki Dashboard API, Catalyst Center, cloud provider APIs, GitHub and GitLab
  - The Ansible `uri` module and most Terraform providers make these same calls underneath

### Methods map to CRUD

:::wide
| CRUD | Method | Example request | Typical success response |
|---|---|---|---|
| Create | `POST` | `POST /api/v1/vlans` with a JSON body | `201 Created` plus a `Location` header |
| Read | `GET` | `GET /api/v1/vlans/30` | `200 OK` with the resource in the body |
| Update (replace) | `PUT` | `PUT /api/v1/vlans/30` with the complete object | `200 OK`, or `204 No Content` |
| Update (modify) | `PATCH` | `PATCH /api/v1/vlans/30` with only the changed fields | `200 OK`, or `204 No Content` |
| Delete | `DELETE` | `DELETE /api/v1/vlans/30` | `204 No Content` (some APIs send `200`) |
:::

- ==PUT replaces== the whole resource
  - Any field you leave out is removed or reset to its default
  - Some APIs also let `PUT` create a resource at a URI the client picks
- ==PATCH modifies== only the fields you send; the rest stay as they were
- From the lab API in the next topic: VLAN 30 has a `name` and a `description`
  - `PUT {"name": "voip"}` returns `{"id": 30, "name": "voip"}`: the description is gone
  - `PATCH {"description": "Desk phones"}` returns all three fields
- ==Safe== methods only read: `GET`, `HEAD`, `OPTIONS`
- ==Idempotent== methods leave the server in the same state no matter how many times you send them
  - The safe methods, plus `PUT` and `DELETE`
  - A second `DELETE` returns `404`, but the VLAN is still gone: same state, different response code
  - `POST` is neither: send it twice and you get two resources or a `409 Conflict`
  - `PATCH` is not guaranteed idempotent (a patch that appends to a list adds twice)
- Why automation cares: a script or pipeline can safely retry an idempotent call after a timeout

### Headers
- ==Request headers== describe the client and the body it sends; ==response headers== describe the result
- `Name: value` lines between the first line and the body
  - Header names are case-insensitive
  - A blank line ends the headers; the body follows

:::figure wide 2.3-request-response.svg | One request and one response. Every HTTP message has the same four parts: a first line, headers, a blank line, and an optional body.

:::wide
| Header | Sent by | Purpose |
|---|---|---|
| `Authorization` | client | Credentials: `Bearer <token>`, or `Basic` with `user:pass` in base64 (encoded, not encrypted) |
| `X-API-Key` | client | A vendor-specific API key header; the name varies by product |
| `Content-Type` | both | Format of the body in this message, such as `application/json` |
| `Accept` | client | Formats the client is willing to receive |
| `Location` | server | URI of a newly created resource (`201`) or of a redirect target (`3XX`) |
| `ETag` | server | Version tag of the resource; the client sends it back in `If-None-Match` (cache check) or `If-Match` (only update if unchanged) |
| `WWW-Authenticate` | server | Sent with `401`; names the authentication scheme the server expects |
| `Retry-After` | server | Seconds to wait after a `429` or `503` |
| `X-RateLimit-Limit`, `X-RateLimit-Remaining` | server | Your quota and the calls left in this window (a common convention; exact names vary by vendor) |
:::

- `curl -v` prints the request headers (`>`) and the response headers (`<`)

```console label="Terminal"
$ API=http://127.0.0.1:18300/api/v1
$ AUTH="Authorization: Bearer s3cr3t-admin"
$ curl -sv -H "$AUTH" $API/vlans/10
> GET /api/v1/vlans/10 HTTP/1.1
> Host: 127.0.0.1:18300
> User-Agent: curl/8.5.0
> Accept: */*
> Authorization: Bearer s3cr3t-admin
>
< HTTP/1.1 200 OK
< X-RateLimit-Limit: 100
< X-RateLimit-Remaining: 99
< ETag: "bc2bc3803223"
< Content-Type: application/json
< Content-Length: 61
```

- Send the ETag back and an unchanged resource costs no body

```console label="Terminal"
$ ET='If-None-Match: "bc2bc3803223"'
$ curl -si -H "$AUTH" -H "$ET" $API/vlans/10
HTTP/1.1 304 Not Modified
ETag: "bc2bc3803223"
Content-Length: 0
```

### Response codes
- A ==response code== (status code) is three digits plus a reason phrase on the first line of every response
  - The first digit is the ==class==: `2XX`, `3XX`, `4XX`, `5XX`; `1XX` (informational) rarely matters to scripts
  - Test the number, never the phrase: HTTP/2 does not send phrases at all

:::wide
| Code | Name | What it tells your script |
|---|---|---|
| **2XX** | **Success** | **The request worked** |
| `200` | OK | Result is in the body |
| `201` | Created | New resource; its URI is in `Location` |
| `204` | No Content | Worked, nothing to return (typical for `DELETE`) |
| **3XX** | **Redirection** | **Look somewhere else** |
| `301` | Moved Permanently | Resource has a new URI for good; update the script (`curl -L` follows it) |
| `302` | Found | Temporary redirect, often to a login page; keep using the old URI |
| `304` | Not Modified | Your cached copy (by `ETag`) is current; no body |
| **4XX** | **Client error** | **Fix the request; resending it unchanged will fail again** |
| `400` | Bad Request | Malformed request, such as invalid JSON |
| `401` | Unauthorized | Not authenticated: token missing, wrong, or expired |
| `403` | Forbidden | Authenticated, but this identity is not allowed to do this |
| `404` | Not Found | Wrong URI, or the resource does not exist |
| `409` | Conflict | Clashes with current state: duplicate ID, edit collision |
| `422` | Unprocessable Content | Valid JSON, but a value fails validation (older name: Unprocessable Entity) |
| `429` | Too Many Requests | Rate limit hit; wait for `Retry-After` |
| **5XX** | **Server error** | **The request may be fine; the service is not** |
| `500` | Internal Server Error | Unhandled error inside the application |
| `502` | Bad Gateway | A proxy or load balancer got no valid answer from the backend |
| `503` | Service Unavailable | Overloaded or in maintenance; often sends `Retry-After` |
| `504` | Gateway Timeout | A proxy gave up waiting for the backend |
:::

- `401` versus `403`, from the lab API

```console label="Terminal"
$ curl -si $API/vlans
HTTP/1.1 401 Unauthorized
WWW-Authenticate: Bearer realm="vlan-api"

{"error": "missing or invalid token"}
$ RO="Authorization: Bearer s3cr3t-viewer"
$ curl -si -X DELETE -H "$RO" $API/vlans/10
HTTP/1.1 403 Forbidden

{"error": "token is read-only"}
```

- A `301` from the old, unversioned path

```console label="Terminal"
$ OLD=http://127.0.0.1:18300/api/vlans
$ curl -si -H "$AUTH" $OLD
HTTP/1.1 301 Moved Permanently
Location: /api/v1/vlans
$ curl -sL -H "$AUTH" $OLD | jq length
2
```

:::exam
- `401` means the server does not know who you are (fix the credential); `403` means it knows and says no (fix the permission). A scenario with a valid token that cannot delete is `403`.
- "Change one field without sending the whole object" is `PATCH`; "replace the object" is `PUT`; "create" is `POST`, answered by `201` and a `Location` header.
- A `4XX` points at the request, a `5XX` at the service. `502` and `504` come from the proxy in front of the application, so look at the backend behind it.
:::
