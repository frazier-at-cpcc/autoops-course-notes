### Networks defined in code
- ==Virtual network infrastructure configuration==: subnets, routers, route tables, load balancers, firewalls, and DNS declared in files, not clicked together in a console
  - Reviewed, versioned, and drift-checked like any code; a second region is the same code with new variables

:::figure wide 2.1-vpc.svg | The example in this topic: two availability zones, public subnets for the load balancer and NAT gateway, private subnets for servers, one route table per tier, and a DNS alias in front.

### Subnets
- A ==VPC== (virtual private cloud) gets one CIDR block; ==subnets== carve it up, one subnet per availability zone per tier
  - ==Public subnet==: its route table sends `0.0.0.0/0` to an internet gateway
  - ==Private subnet==: no route from the internet; outbound only, through NAT
- AWS keeps 5 addresses in every subnet (the first four and the last), so a `/24` has 251 usable

```console label="terraform console"
> cidrsubnet("10.20.0.0/16", 8, 1)
"10.20.1.0/24"
> cidrsubnet("10.20.0.0/16", 8, 10)
"10.20.10.0/24"
> cidrhost("10.20.10.0/24", 25)
"10.20.10.25"
```

```hcl label="network.tf (excerpt)"
locals {
  azs     = ["us-east-1a", "us-east-1b"]
  public  = ["10.20.0.0/24", "10.20.1.0/24"]
  private = ["10.20.10.0/24", "10.20.11.0/24"]
}

resource "aws_subnet" "public" {
  count             = 2
  vpc_id            = aws_vpc.lab.id
  availability_zone = local.azs[count.index]
  cidr_block        = local.public[count.index]

  map_public_ip_on_launch = true
}
```


### Routers and route tables
- Every VPC has an implicit ==router==; you never deploy it, you program it with ==route tables==
  - Each table starts with a `local` route for the VPC CIDR
  - Each subnet is associated with exactly one route table
- Gateways are the next hops
  - ==Internet gateway==: two-way internet access for public subnets
  - ==NAT gateway==: sits in a public subnet with an Elastic IP; lets private subnets start outbound connections (patches, APIs) while blocking inbound ones

```hcl label="routing.tf (excerpt)"
resource "aws_route_table" "private" {
  vpc_id = aws_vpc.lab.id
  route {
    cidr_block     = "0.0.0.0/0"
    nat_gateway_id = aws_nat_gateway.nat.id
  }
}

resource "aws_route_table_association" "public" {
  count          = 2
  subnet_id      = aws_subnet.public[count.index].id
  route_table_id = aws_route_table.public.id
}
```

### Firewalls and security groups
- A ==security group== is a stateful firewall attached to an interface (instance, load balancer, database)
  - Allow rules only; anything not allowed is dropped; replies return automatically
  - A rule can name another security group as its source instead of an address range
- The network ACL on the subnet is the stateless second layer (see the ACL table in the workload configuration topic)

```hcl label="firewall.tf (excerpt)"
resource "aws_security_group" "web" {
  name   = "lab-web"
  vpc_id = aws_vpc.lab.id
  ingress {
    protocol        = "tcp"
    from_port       = 80
    to_port         = 80
    security_groups = [aws_security_group.lb.id]
  }
}
```

- Only the load balancer can reach the web servers on port 80; no address ranges to keep current
- Large rule sets: one `aws_vpc_security_group_ingress_rule` resource per rule

### Load balancers
- A ==load balancer== spreads traffic across healthy targets and gives clients one stable name
  - ==Application load balancer== (layer 7): HTTP and HTTPS, path and host routing, TLS termination
  - ==Network load balancer== (layer 4): TCP, UDP, and TLS at very high rates, static IPs
- Three parts in code
  - `aws_lb`: `load_balancer_type = "application"`, `subnets = aws_subnet.public[*].id` (a splat: every public subnet ID)
  - `aws_lb_target_group`: the servers plus a ==health check== (`path = "/healthz"`); unhealthy targets get no traffic
  - `aws_lb_listener`: port 443 with the certificate (`certificate_arn`), forwarding to the target group

### DNS records as code
- ==Public hosted zone==: names on the internet; ==private hosted zone==: names that resolve only inside the attached VPCs
- An ==alias record== points a name at an AWS resource; it follows the load balancer's changing IPs and works at the zone apex

```hcl label="dns.tf (excerpt)"
resource "aws_route53_record" "www" {
  zone_id = aws_route53_zone.public.zone_id
  name    = "www.lab.example.com"
  type    = "A"
  alias {
    name                   = aws_lb.web.dns_name
    zone_id                = aws_lb.web.zone_id
    evaluate_target_health = true
  }
}
```

- The internal record is a plain A record: `db.lab.internal`, TTL 300, `10.20.10.25`
- The same building blocks exist in every cloud; only the resource names change

| Objective term | AWS (Terraform resource) | Azure (Terraform resource) |

| Virtual network | `aws_vpc` | `azurerm_virtual_network` |

### Checking it without an AWS account
- `terraform validate` checks syntax, types, and references; it needs the provider but no credentials
- `terraform plan` must call the AWS API, so without credentials it stops

```console label="Terminal"
$ terraform init -input=false
$ terraform validate
Success! The configuration is valid.
$ terraform plan -var-file=lab.tfvars
Error: No valid credential sources found
```

- Validate also catches broken references: `aws_subnet.public.id` on a counted resource fails with `Error: Missing resource instance key`; the fix is an index such as `[0]`

- Run `terraform fmt -check` and `terraform validate` in CI on every pull request; save `plan` and `apply` for the stage that holds cloud credentials

:::exam
- Match the term to the job: a route table decides the next hop, a security group filters traffic to an interface, a NAT gateway gives private subnets outbound-only internet access, an internet gateway makes a subnet public.
- A scenario where instances in a private subnet cannot download updates points at the private route table: it is missing `0.0.0.0/0` to a NAT gateway. Adding an internet gateway route would make the subnet public instead.
- `terraform validate` needs no cloud credentials; `plan` and `apply` do.
:::
